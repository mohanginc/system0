# system0

주문 엑셀의 상품명을 정리하는 앱입니다. HTML·CSS·JavaScript, Node.js, SQLite로 구성하며, 업무 화면과 API 및 디스코드 송장 처리를 제공합니다.

## 디스코드 송장 처리

지정한 직원·텍스트 채널에서 `@system0 네이버 송장 입력용 파일 만들어줘`와 함께 네이버·로젠 파일을 각각 하나씩 첨부합니다. `/송장` 명령도 사용할 수 있습니다. 기존 상품명 작업에 저장된 주문 근거를 사용합니다.

정상 매칭은 엑셀을 반환합니다. 복수 송장은 해당 출고의 **교체** 또는 **분할 대표** 번호를 선택하고 **선택 완료 · 엑셀 만들기**를 누릅니다. 정정 번호만 담은 파일은 “이번 파일의 송장으로 교체해줘”라고 요청하고 표시된 범위를 한 번 확인합니다. 실제 충돌이나 불명확한 연결은 system0 검토 화면에서 확인합니다.

**보관 엑셀 받기**는 생성 당시 파일이며, 변경한 선택은 **현재 매칭으로 새 엑셀**로 받습니다. **최신 상태**, **네이버 등록 확인** 버튼과 `/송장파일`, `/송장상태`, `/등록확인` 명령도 제공합니다. 네이버 실제 송장 등록은 수행하지 않습니다. LLM의 절차 지침은 [채팅 업무 절차](prompts/discord-workflows.md)에서 읽으며 기능 변경 시 관련 대화 검증과 함께 갱신합니다.

1. Discord 개발자 포털에서 `system0` 앱을 만들고 서버에 봇을 초대합니다. 설치 범위는 `bot`, `applications.commands`, 권한은 채널 보기·메시지 보내기·파일 첨부·링크 임베드·메시지 기록 보기입니다. 관리자 권한은 필요하지 않습니다. 봇을 멘션한 메시지만 받으므로 Message Content Intent는 사용하지 않습니다.
2. Discord 사용자 설정의 고급에서 개발자 모드를 켜고, 서버·사용할 텍스트 채널·직원의 숫자 ID를 복사합니다.
3. PowerShell에서 `./scripts/configure-discord.ps1`을 실행해 ID와 봇 토큰·네이버 파일 암호를 입력합니다. 토큰은 화면에 표시되지 않으며 `%LOCALAPPDATA%/system0/discord.env`에 저장됩니다. 채팅이나 Git에는 넣지 않습니다. Linux 설정 파일은 `/etc/system0-discord.env`이며 `DISCORD_ENV_FILE`로 경로를 지정할 수 있습니다.
4. system0 서버를 재시작하고 별도 터미널에서 `npm run discord:start`를 실행합니다. 봇과 system0은 같은 컴퓨터에서 실행하며 `DISCORD_API_BASE`는 해당 로컬 포트입니다. 명령은 지정한 서버에만 등록됩니다.

구글 운영서버는 `scripts/system0-discord.service`를 사용해 봇을 자동 실행합니다. `/etc/system0-discord.env`는 `root:system0`, 권한 `640`으로 두고 `DISCORD_API_BASE=http://127.0.0.1:3000`, `SYSTEM0_PUBLIC_ORIGIN=https://system0.babestellar.com`을 지정합니다. 테스트에서 운영으로 옮길 때는 테스트 봇을 종료하고 내부 연결 키를 새로 생성합니다.

파일은 하나당 10MB이며 `.xls`·`.xlsx`를 지원합니다. 암호화된 네이버 파일은 비공개 설정의 암호로 읽습니다. 자연어 해석은 기존 AI 설정을 사용하며 고정 명령에는 AI가 필요하지 않습니다. 기존 엑셀 보관본은 우선 그대로 반환하고, 화면에서 명시적으로 재생성할 때만 현재 매칭을 사용합니다. 서명된 작업 버튼은 다른 채널로 옮겨 사용할 수 없습니다.

Discord의 [봇 시작 안내](https://docs.discord.com/developers/quick-start/getting-started)와 [앱 설치 안내](https://docs.discord.com/developers/resources/application)를 참고합니다.

## 운영 컴퓨터 설치

Windows 10·11의 64비트 환경에서 `outputs/installer/system0-setup-0.1.4.exe` 하나를 옮겨 실행합니다. Node.js와 라이브러리가 포함되어 있으며 관리자 권한은 필요하지 않습니다. 최초 설치 화면에서 API 키를 입력하고, 바탕화면 **system0 주문 상품명 정리**를 실행합니다. 브라우저가 자동으로 열리며 서버 종료는 실행 창에서 `Ctrl+C`입니다.

프로그램은 `%LOCALAPPDATA%/Programs/system0`, 설정은 `%LOCALAPPDATA%/system0/.env`, DB는 기존 기본 경로에 저장합니다. 운영판 기본 접속 주소는 <http://127.0.0.1:3100>입니다. 새 컴퓨터에는 빈 DB로 시작하며, 기존 작업 이전은 아래 백업·복구 방법을 따릅니다. 재설치와 프로그램 제거는 DB와 설정을 보존합니다. 업데이트 전에 실행 중인 앱을 종료합니다.

설치 파일을 다시 만들 때 `npm.cmd run installer:build`를 실행합니다. 공식 Node.js 24.21.0과 Inno Setup 7.1.0을 내려받아 SHA-256을 확인한 뒤, 실행에 필요한 파일만 패키징합니다. 개발 컴퓨터의 `.env`와 DB는 포함하지 않습니다. `npm.cmd run installer:test`는 완성된 EXE를 임시 폴더에 설치해 번들 실행·엑셀 다운로드·업데이트·데이터 보존을 확인하고 정리합니다. 실제 운영 DB와 키는 사용하지 않으며 API 호출 비용도 발생하지 않습니다.

0.1.4 설치판의 **상품명 정리·출고 보드·송장 매칭과 엑셀·등록 상태 조회**는 단일 CMD 패치로 적용할 수 있습니다. 날짜·내역 패널 접기와 최신 화면 수정도 포함합니다. 프로젝트 폴더에서 PowerShell로 직접 빌드하고 검사합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File installer/build-patch.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test/patch.test.ps1
```

기본 결과는 `outputs/installer/system0-patch-invoices.cmd`입니다. 다른 출력 경로가 필요하면 빌드 명령에 `-OutputFile`을 지정합니다. 이 파일 하나를 운영 컴퓨터로 옮긴 뒤 앱 실행 창에서 `Ctrl+C`로 종료하고, CMD를 더블클릭합니다. 적용 후 기존 아이콘으로 앱을 실행하고 브라우저에서 `Ctrl+F5`를 누릅니다.

이 패치는 기본 경로 `%LOCALAPPDATA%/Programs/system0`에 설치된 0.1.4 전용입니다. 서버·상품명 지침·업무 화면을 교체하고 네이버 인증과 암호화 엑셀 읽기에 필요한 라이브러리를 포함합니다. 모든 파일의 무결성을 확인한 뒤 적용하며, 교체 중 실패하면 원래 프로그램 파일로 복구합니다. DB·`.env`·Node.js는 유지하며 다음 실행에서 기존 DB에 필요한 테이블·컬럼을 추가합니다. 과거 작업과 검수 내용은 보존합니다. 처음 설치하는 컴퓨터에는 전체 설치 파일이 필요합니다.

**신규 주문현황**을 사용하려면 운영 컴퓨터의 `%LOCALAPPDATA%/system0/.env`에도 `NAVER_CLIENT_ID`와 `NAVER_CLIENT_SECRET`을 입력해야 합니다. 인증정보·개발 DB·테스트 작업은 패치에 포함하지 않습니다.

기존 0.1.4 설치 파일과 이전 `system0-patch-review-save.cmd`에는 기존 이름 재사용과 AI 호출 내역이 포함되지 않습니다. 이미 설치했다면 새 상품명 패치를 적용합니다.

## 개발 컴퓨터 실행

Node.js 24 이상이 필요합니다. 프로젝트 폴더에서 실행합니다.

```powershell
npm.cmd ci
npm.cmd start
```

브라우저에서 <http://127.0.0.1:3000>에 접속합니다. 서버 종료는 실행한 터미널에서 `Ctrl+C`입니다.

`.env`에 `OPENAI_API_KEY`를 설정합니다. 기본 모델은 `gpt-6.1-sol`이며, 변경할 때만 `OPENAI_MODEL`을 지정합니다. 설정 예시는 `.env.example`에 있습니다. 키는 백엔드에서만 읽습니다. `.env`는 Git에서 제외되지만 OneDrive 동기화는 별개입니다.

## 기능과 사용

파일 불러오기 → 상품명 정리 → 직원 검수·저장 → 엑셀 다운로드 순서로 사용합니다. 현재 지침으로 정리된 이름은 재사용하고, 이전 지침의 이름은 해당 상품의 다음 주문에서 LLM으로 한 번 갱신합니다. **AI 호출 내역**에서 날짜·목적별 실제 호출 횟수를 확인할 수 있습니다. 화면별 사용법, 데이터 처리 범위와 API는 [기능 안내](docs/features.md)에 정리합니다.

**AI 호출 내역**에는 호출별 토큰과 추정 비용(USD), 날짜·목적별 합계와 산정된 호출의 평균도 표시합니다. `gpt-6.1-sol`의 입력·캐시 읽기·캐시 쓰기·출력 단가를 구분하며 사용량이나 단가가 없으면 미산정으로 남깁니다. 새 호출은 `llm_calls.cost_json`에 당시 계산 기준을 보존합니다. 기존 호출은 현재 Standard·기본 캐시 단가를 가정한 추정이며 세금·계약 할인과 실제 청구액은 포함하지 않습니다. 단가 기준일과 공식 출처는 `lib/llm-pricing.mjs`에 있습니다.

**송장 처리**(`/invoices.html`)는 최종 네이버 주문파일을 기준으로 날짜와 관계없이 저장 주문·택배사 송장을 연결해 수동 업로드용 엑셀을 만들고 등록 상태를 조회합니다. 파일에서 빠진 관련 주문의 수동 등록 여부도 별도로 조회합니다. 위 최신 CMD 패치에 포함되며 기존 전체 설치 파일만 사용한 컴퓨터에는 패치를 적용해야 합니다.

### 상품 바코드

정리된 제품명 아래 회사 바코드를 표시하며, 확인된 연결이 없으면 **바코드 없음**으로 남깁니다. 출고보드는 같은 바코드·출고 유형을 묶고 조회 범위에서 가장 많이 쓰인 제품명을 제목으로 표시합니다. 판매처 말머리는 연결에서 무시하지만 정상·리퍼·맞교환은 구분합니다. 주문 원본과 엑셀 컬럼은 유지합니다.

**상품·바코드**(`/products.html`)에서 새 상품과 13자리 바코드를 등록하고, 바코드 없는 정리명을 기존 상품에 연결합니다. 연결은 같은 이름의 기존 활성 주문과 이후 주문에 적용됩니다. 중복 바코드와 다른 SKU로의 재연결은 거부합니다. 상품 등록 자체로 비슷한 이름을 자동 연결하지 않습니다.

처음 실행할 때 [SKU 초기 자료](data/sku-catalog.json)의 35개 코드를 `sku_products`·`sku_aliases` 테이블에 넣습니다. 이후 관리 내용은 DB와 백업에 저장되며 재시작·배포로 덮어쓰지 않습니다. 회사명 코드 하나는 연결 대상에서 제외합니다. 기존 주문과 저장한 제품명 수정에도 같은 DB 연결을 사용하며, `rows.sku_barcode`는 문자열입니다. 배포할 때 `lib/sku.mjs`, `lib/products.mjs`, `data/sku-catalog.json`과 관리 화면을 함께 포함해야 합니다.

## 저장과 백업

Windows 기본 DB는 `%LOCALAPPDATA%/system0/system0.sqlite`입니다. 이 개발 컴퓨터는 Codex의 AppData 경로 중복 해석을 피하도록 `.env`의 `DATABASE_PATH`를 `C:/Users/s705d/system0-data/system0.sqlite`로 지정합니다. 운영 설치판의 기본 경로는 그대로입니다. DB는 OneDrive 밖에 두며, 업로드한 원본 파일, 원본 행과 작업 이력도 함께 저장합니다.

화면 아래 **데이터 백업**은 실행 중인 DB의 일관된 백업본을 다운로드합니다. 백업본은 OneDrive 등에 보관할 수 있습니다. 복구할 때는 서버를 종료하고 기존 DB를 다른 폴더에 보관합니다. 같은 이름의 `-wal`·`-shm` 파일이 남아 있으면 함께 옮겨 보관한 뒤, 백업본을 설정된 DB 경로에 복사하여 실행합니다. 복구 후 작업 목록과 상품명·검수 내용을 확인하세요. 실행 중인 DB 파일을 직접 동기화하지 않습니다.

기본 서버는 이 컴퓨터의 `127.0.0.1`에서만 접근할 수 있습니다. 같은 서버의 HTTPS 인증 프록시 뒤에서 운영할 때 `SYSTEM0_PUBLIC_ORIGIN=https://system0.babestellar.com`을 지정하면 해당 도메인의 접속과 같은 Origin의 쓰기 요청을 추가로 허용합니다. 끝 슬래시 없이 입력하며, Node.js는 계속 `127.0.0.1`에서만 실행합니다. 이 설정 자체는 로그인 기능이 아니므로 프록시의 직원별 인증을 함께 설정합니다.

테스트는 가져오기 누락·원본 보존, 직원 수정 보존, 잘못된 AI 응답, 중간 실패·재시도, 삭제한 작업·행의 제외와 DB 보존, 엑셀 내보내기와 백업 복구를 확인합니다. 기존 이름 재사용·목적별 호출 집계와 업무 API만으로 업로드·정리·검수·다운로드하는 흐름도 확인합니다. 테스트의 AI 응답은 모의 응답이며 API 비용이 발생하지 않습니다. 참고 주문 샘플이 있으면 실제 파일도 검사합니다.
